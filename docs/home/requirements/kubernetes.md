# Kubernetes

- Any distribution of Kubernetes could be used, e.g.: EKS, AKS, Rancher, Vanilla Kubernetes. Of the known limitations, we have not tested with Redhat OpenShift.
- ODM requires to store a state inside of Kubernetes, this is under [StorageClass](https://kubernetes.io/docs/concepts/storage/storage-classes/) and the corresponding controller responsability.
- For publishing ODM we use Ingress, it requires a [IngressClass](https://kubernetes.io/docs/concepts/services-networking/ingress/) and the corresponding controller.
- The Ingress routes each path of ODM straight to the Service that serves it. `/` and the pages of the UI before `/ui`, which old links still use, go to the `applications` Service, which answers them with a `301` redirect to their `/ui` pages. The Ingress controller does the rest of what ODM expects at its entry point, configured through the `ingress` values of the Helm chart:
    - `X-Forwarded-Proto` on every request, which the AWS Load Balancer Controller and ingress-nginx set without configuration. The `applications` Service answers `404` for `/frontend/endpoint/actuator/prometheus`, `/frontend/endpoint/proxy` and every path under them to a request that carries `X-Forwarded-Proto` or `X-Forwarded-For`. Prometheus scrapes the pods directly, without these headers, and gets the metrics. `frontend.metrics.public: "true"` in the chart's `applications.files`, in `/var/lib/genestack/properties/application.yaml`, serves these paths through the Ingress too.
    - The security headers `Strict-Transport-Security`, `X-Content-Type-Options` and `X-Frame-Options`.
- The Helm chart has examples of this for two controllers: `odm/examples/ingress-alb.yaml` for the [AWS Load Balancer Controller](../clouds/aws.md), and `odm/examples/ingress-nginx.yaml` for the community [ingress-nginx](https://kubernetes.github.io/ingress-nginx/). The ingress-nginx example uses a server snippet, so the controller's ConfigMap needs `allow-snippet-annotations: "true"` and `annotations-risk-level: Critical`.
- (Recommendation) To work with [SSL/TLS](https://kubernetes.io/docs/concepts/services-networking/ingress/#tls), for Ingress, provide certificates via Kubernetes secrets or configure them on an external Load Balancer.
