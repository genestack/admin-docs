# Kubernetes

- Any distribution of Kubernetes could be used, e.g.: EKS, AKS, Rancher, Vanilla Kubernetes. Of the known limitations, we have not tested with Redhat OpenShift.
- ODM requires to store a state inside of Kubernetes, this is under [StorageClass](https://kubernetes.io/docs/concepts/storage/storage-classes/) and the corresponding controller responsability.
- For publishing ODM we use Ingress, it requires a [IngressClass](https://kubernetes.io/docs/concepts/services-networking/ingress/) and the corresponding controller.
- The Ingress routes each path of ODM straight to the Service that serves it: `/`, `/frontend` and `/api` to the `applications` Service. `applications` answers `/` and the pages of the UI before `/ui`, which old links still use, with a `301` redirect to their `/ui` pages. The Ingress routes no other path to `applications`, so it does not route its actuator, at `/actuator`. Whatever reaches port 8080 of an `applications` pod reaches the actuator, its metrics and full health details among it.
- The Ingress controller must set `X-Forwarded-For` on every request, which the AWS Load Balancer Controller and F5's NGINX Ingress Controller do without configuration. `applications` takes the client's IP address from it, and the audit log records that address.
- The Helm chart has examples of the `ingress` values for two controllers: `odm/examples/ingress-alb.yaml` for the [AWS Load Balancer Controller](../clouds/aws.md), and `odm/examples/ingress-nginx.yaml` for [F5's NGINX Ingress Controller](https://github.com/nginx/kubernetes-ingress).
    - The nginx example sets `nginx.org/*` annotations and the IngressClass `nginx`, the default of F5's Helm chart. Its `nginx.org/location-snippets` sets `proxy_request_buffering off;`, which streams uploads to `applications` as they arrive. The controller rejects an Ingress with a snippet unless it runs with `-enable-snippets`, `controller.enableSnippets: true` in its Helm chart.
    - The `-enable-snippets` flag lets any Ingress on the controller, from any namespace, add raw nginx configuration. Without the flag, remove the snippet from the example and set `location-snippets: proxy_request_buffering off;` in the controller's ConfigMap, `controller.config.entries` in its Helm chart: the controller then streams uploads for every Ingress it serves. With neither, the controller buffers each upload before it passes it on.
    - The community [ingress-nginx](https://kubernetes.github.io/ingress-nginx/) controller reached its end of life in March 2026 and gets no security fixes. The nginx example does not support it: ingress-nginx reads `nginx.ingress.kubernetes.io/*` annotations and ignores `nginx.org/*` ones, so the example's upload size and timeouts do not apply.
- (Recommendation) To work with [SSL/TLS](https://kubernetes.io/docs/concepts/services-networking/ingress/#tls), for Ingress, provide certificates via Kubernetes secrets or configure them on an external Load Balancer.
