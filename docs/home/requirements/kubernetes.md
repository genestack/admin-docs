# Kubernetes

- Any distribution of Kubernetes could be used, e.g.: EKS, AKS, Rancher, Vanilla Kubernetes. Of the known limitations, we have not tested with Redhat OpenShift.
- ODM requires to store a state inside of Kubernetes, this is under [StorageClass](https://kubernetes.io/docs/concepts/storage/storage-classes/) and the corresponding controller responsability.
- For publishing ODM we use Ingress, it requires a [IngressClass](https://kubernetes.io/docs/concepts/services-networking/ingress/) and the corresponding controller.
- The Ingress routes each path of ODM straight to the Service that serves it. `/` and the pages of the UI before `/ui`, which old links still use, go to the `applications` Service, which answers them with a `301` redirect to their `/ui` pages. The Ingress controller does the rest of what ODM expects at its entry point, configured through the `ingress` values of the Helm chart:
    - `X-Forwarded-Proto` on every request, which the AWS Load Balancer Controller and F5's NGINX Ingress Controller set without configuration. The `applications` Service answers `404` for `/frontend/endpoint/actuator/prometheus`, `/frontend/endpoint/proxy` and every path under them to a request that carries `X-Forwarded-Proto` or `X-Forwarded-For`. Prometheus scrapes the pods directly, without these headers, and gets the metrics. `frontend.metrics.public: "true"` in the chart's `applications.files`, in `/var/lib/genestack/properties/application.yaml`, serves these paths through the Ingress too.
    - The security headers `Strict-Transport-Security`, `X-Content-Type-Options` and `X-Frame-Options`.
- The Helm chart has examples of this for two controllers: `odm/examples/ingress-alb.yaml` for the [AWS Load Balancer Controller](../clouds/aws.md), and `odm/examples/ingress-nginx.yaml` for [F5's NGINX Ingress Controller](https://github.com/nginx/kubernetes-ingress), 5.5 or later.
    - The nginx example sets `nginx.org/*` annotations and the IngressClass `nginx`, the default of F5's Helm chart. Its `nginx.org/location-snippets` sets `proxy_request_buffering off;`, which streams uploads to `applications` as they arrive. The controller rejects an Ingress with a snippet unless it runs with `-enable-snippets`, `controller.enableSnippets: true` in its Helm chart. Without the snippet, the controller buffers each upload before it passes it on.
    - The community [ingress-nginx](https://kubernetes.github.io/ingress-nginx/) controller reached its end of life in March 2026 and gets no security fixes. The nginx example does not support it: ingress-nginx reads `nginx.ingress.kubernetes.io/*` annotations and ignores `nginx.org/*` ones, so the example's upload size, timeouts and security headers do not apply.
- (Recommendation) To work with [SSL/TLS](https://kubernetes.io/docs/concepts/services-networking/ingress/#tls), for Ingress, provide certificates via Kubernetes secrets or configure them on an external Load Balancer.
